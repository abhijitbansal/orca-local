# Syncing the local-only fork with upstream

This fork removes the cloud, mobile, telemetry-upload, updater and ingress code of
`stablyai/orca` (see [local-only-architecture.md](./local-only-architecture.md)).
Pulling an upstream release is a merge, a small set of conflict resolutions, and a
guard run. Three tiers keep the conflicts mechanical:

1. **Whole-unit deletes.** Most removals delete entire files and directories. When
   upstream edits a file we deleted, the merge reports modify/delete: resolve with `git rm`.
2. **Hot-file line deletions.** A few registration sites had lines deleted, never
   rewritten. A conflict there means upstream touched a neighbor of a line we removed.
   Keep our deletion and take upstream's other changes (playbook below).
3. **The guard.** `pnpm run check:local-only` fails on anything that reintroduces
   cloud egress, so a clean merge that quietly re-adds a removed feature is caught.

## One-time setup

```bash
git remote add upstream https://github.com/stablyai/orca.git
```

This is a user action. It is documented here, not run by any script. The playbook's file
list is built from `git diff --stat upstream/main...HEAD --diff-filter=M` (our changes
relative to upstream). It works before the first merge and after every later one.

## The merge loop

Run on a topic branch, not on the branch you ship from.

1. `git fetch upstream`
2. `git merge upstream/main`
3. Resolve modify/delete conflicts on files we deleted with `git rm <path>`. Do not port upstream's edit to a deleted file.
4. Resolve Tier-2 hot-file conflicts with the playbook below.
5. `pnpm install`
6. `pnpm tc`
7. `pnpm run check:local-only`
8. `pnpm test`

Then run `pnpm lint` (it includes the guard, the localization gates, the RPC catalog
check, and the reliability-gates check). Compare failing test files with
`notes/local-only/before/failing-files.txt`; the failures listed there are present
on pristine upstream too.

If step 6 fails on an import of a deleted module, upstream added a new caller of a
removed feature. Delete the caller (see "Classifying a new upstream feature").

### Locale JSONs

After a merge, `pnpm run verify:localization-catalogs`, `verify:localization-extraction`
and `verify:localization-coverage` fail on keys that are orphaned (used only by code
we deleted) or extra. Prune those keys from all six locale JSONs, then run
`pnpm run sync:localization-runtime-catalog`. If the gates pass, leave the catalogs alone.

## Classifying a new upstream feature

Ask where its data goes, in this order:

1. **Does it call a non-loopback host from Orca's own process?** (A fetch/`net.request`, an SDK, a vendor API, a webhook, a "sync", "share", "invite", "sign in", "update", "feedback", "usage", or "telemetry upload" path.) It is **cloud**: remove it. Delete the whole unit (Tier 1), delete its registration lines (Tier 2), and re-run the guard.
2. **Does it open a listener or accept connections?** A listener must bind a Unix socket, a named pipe, or `127.0.0.1`. Anything else is **cloud**: remove it.
3. **Does it work on files, git (via the CLI), terminals, agents, worktrees or folder workspaces on this machine, or the embedded browser pane?** It is **local**: keep it.
4. **Does it only open a URL in the OS browser (`shell.openExternal`)?** It is **local**, but the URL's host may need an allowlist entry.
5. **Does it create or talk to an `ssh:`/`runtime:` execution host, deploy a relay or orcad, or boot a VM?** It is **remote execution**: remove it (I4). WSL (`wslDistro`, `{ kind: 'wsl' }`) is local and stays.

When an upstream feature mixes both (for example a settings pane with a cloud toggle),
keep the local part and delete the cloud branch, with line deletions rather than rewrites.

## Extending the guard

`config/scripts/check-local-only.mjs` holds the rule lists; its test is
`config/scripts/check-local-only.test.mjs`.

- A new cloud hostname: add it to `FORBIDDEN_HOSTS`, add a test case, and run `pnpm run check:local-only`.
- A new cloud SDK: add it to `FORBIDDEN_MODULES`.
- A legitimate use the rule trips on (a help link, a string, a URL classifier): add `path:rule` to `config/local-only-allowlist.txt` with a one-line justification comment above it. Keep that list short; fix the code first.
- A new bind shape the `wildcard-bind` regex misses: tighten the regex and add a test, do not allowlist.

A merge is done when `pnpm tc`, `pnpm run check:local-only`, and `pnpm test` (compared with `notes/local-only/before/failing-files.txt`) are all at baseline.
