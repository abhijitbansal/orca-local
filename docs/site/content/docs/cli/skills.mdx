Orca ships **skills** that agents load from their skill directories. Skills are **hybrid discovery stubs**: short `SKILL.md` files that tell the agent _when_ to engage Orca and how to load the full guide from the running CLI. Command flags live in the binary so they cannot drift from the app version. The stubs live in this repo's `skills/` folder and the guides in `skill-guides/`; nothing is fetched from a registry.

## Bundled Orca skills

| Skill                                             | Use it for                                                    |
| ------------------------------------------------- | ------------------------------------------------------------- |
| [`orca-cli`](#orca-cli)                           | Worktrees, terminals, files, automations, embedded browser.   |
| [`orchestration`](#orchestration)                 | Multi-agent Runs, tasks, supervised workers, messages, gates. |
| [`computer-use`](#computer-use)                   | Desktop apps via accessibility trees and safe UI actions.     |
| [`orca-emulator`](#orca-emulator)                 | iOS Simulator control.                                        |
| [`orca-emulator-android`](#orca-emulator-android) | Android emulator/device via adb.                              |

Copy a skill folder from `skills/<name>/` into your agent's skill directory (for example `~/.claude/skills/`) to make it available to that agent.

## Hybrid stubs vs the live guide

An installed stub tells the agent to:

1. Resolve the CLI executable for this session (`ORCA_CLI_COMMAND`, `orca-dev`, Linux `orca-ide`, else `orca`).
2. Load the full guide: `orca skills get <topic>` (or `--full` for the long guide).
3. Prefer `--json` and do not invent flags from memory.

```bash
orca skills list
orca skills get orca-cli
orca skills get orchestration --references
orca skills get orchestration --reference recovery-and-cleanup
orca skills get orchestration --full
orca skills installed --json
```

A guide's action gates name conditional references. `--reference <name>` prints one of them alone, so an agent pays for the kernel plus that document instead of the whole package; `--references` lists the names. The name may be bare (`recovery-and-cleanup`) or spelled as the guide writes it (`references/recovery-and-cleanup.md`). `--full` still prints the kernel plus every reference.

Add `--json` when an agent needs deterministic output for automation. `skills show` is an alias for `skills get`.

## Keep skills up to date

Orca updates its own skills itself, with no `npx`, Git, Node or network. A copy counts as Orca's untouched copy when its folder holds only `SKILL.md` and that file matches a version Orca has shipped. Only those copies are rewritten, in place (the shared `~/.agents/skills/<name>` or a real folder in an agent's skills folder such as `~/.claude/skills/<name>`). Anything else is left alone and reported: **You've changed this copy**, or **A different skill already uses this name**. Orca never deletes a folder it did not create.

When this Orca build ships a newer version of a skill you installed, the app:

- Shows an **update available** nudge and badge. Update only touches locations that already hold the skill; it never adds the skill for another agent.
- Opens **Update skills**, which lists every location and what Update does there: **No change**, **Will update**, **Will link**, or **Left alone** with the reason. A copy left alone has a **Replace** choice (off by default); Replace first moves that copy to `~/.agents/.orca-skill-backups/`, then puts Orca's copy in its place.
- Runs exactly the plan you reviewed: if a folder changed after you opened the dialog, that skill reports **Changed since you reviewed it** and nothing is written there.
- Shows the result per skill, for example `Updated · 1 left alone: You've changed this copy`, and a status-bar segment while it runs.

This covers skills installed on this computer. The app does not check WSL projects, SSH hosts or paired Orca servers yet; run `orca skills update` there.

On headless hosts (SSH, containers, CI, `orca serve`) use the CLI. It runs the same planner on the machine that runs it and does **not** need a running Orca app:

```bash
orca skills install                                      # list installable names
orca skills install --skill orca-cli --skill orchestration
orca skills install --skill orca-cli --agent claude,codex
orca skills update --all --dry-run                       # what would change, and the plan digest
orca skills update --all
orca skills update --all --force                         # also replace copies left alone (backup kept)
```

- Default scope is **global**; pass `--local` for the current project only (Orca links only into agent folders the project already has).
- Targets the agents Orca detects on the host plus the shared `.agents/skills` folder. Use `--agent <name>[,<name>…]` to choose (the skills CLI's keys such as `claude-code` still work), or `--agent universal` for the shared folder alone.
- `update` only touches locations that already hold the skill; `install` adds it, including for newly detected agents.
- `--dry-run` prints the plan and its digest without writing. A real run plans again and writes only while the plan still matches.
- `--json` works for dry runs and real runs. The exit code is 1 when a location failed or changed during the run; folders left alone are warnings.

To remove a scanned skill, open its actions menu and choose **Delete…**. For several skills, open the page's **More actions** menu, choose **Delete skills…**, and select the eligible results. Orca explains why a copy cannot be deleted—for example because it is bundled, plugin-managed, read-only, or outside a removable skill folder—before you confirm.

## orca-cli

Load the version-matched command guide with `orca skills get orca-cli`. See [Orca CLI](/docs/cli/overview).

## orchestration

Use this when an agent should coordinate other agents through Runs, tasks, supervised workers, and decision gates. See [Orchestration](/docs/cli/orchestration). Always load `orca skills get orchestration --full` before mutating orchestration state — the legacy `orchestration run` command is retired.

## computer-use

Use this when an agent needs to inspect and operate local desktop app windows. See [Computer use](/docs/cli/computer-use).

## orca-emulator

Use this when an agent should control an iOS Simulator from inside Orca through `orca emulator` commands.

## orca-emulator-android

Use for adb-connected Android AVDs/devices: list/boot, tap/swipe/type, hardware buttons, install/launch, permissions, accessibility tree, logcat. Load details with `orca skills get orca-emulator-android`.

## Discovery sources

Orca's skill UI scans installed skill homes for Claude, Codex, Agent Skills, and **OMP** (`~/.omp/agent/skills`), so skills placed there show up without a manual symlink.

## Add your own skills

Any folder with a `SKILL.md` file works as a skill. Put one in your agent's skill directory to give it company-specific powers.

## MCP servers

Model Context Protocol (MCP) servers expose external tools to compatible agents. Register MCP endpoints in your agent CLI's own configuration; those tools appear inside agent CLIs that support MCP.
