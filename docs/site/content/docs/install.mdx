This is a local-only fork of Orca. It ships no prebuilt downloads, no Homebrew cask, no package-manager repository, and no auto-update. You build the app from source and update it by merging upstream and rebuilding.

## Build from source

You need Node.js 24, [pnpm](https://pnpm.io) 12, and git. From a checkout of the repo:

```bash
pnpm install

# macOS
pnpm build:mac

# Linux
pnpm build:linux

# Windows
pnpm build:win
```

The packaged app lands in `dist/`. To run from source without packaging, use `pnpm dev`. Per-platform prerequisites and contributing notes are in `.github/CONTRIBUTING.md`.

## First launch

On first launch Orca will:

- Ask for access to your home directory so it can add repos.
- Offer to import `~/.claude`, `~/.codex`, and Ghostty terminal settings if present.
- Drop you on an empty landing screen where you add your first repo.

## Updates

Orca never checks for updates and never contacts a release server. To update:

1. Add the upstream remote once: `git remote add upstream https://github.com/stablyai/orca.git`.
1. Fetch and merge the release you want, resolve conflicts, and rebuild.

The full procedure, including a per-file conflict playbook, is in `docs/reference/local-only-upstream-sync.md` in the repo. Your worktree data stays where it is across rebuilds, and older builds keep working against it.

<Callout title="Staying on a version">
  Because nothing updates itself, an installed build stays exactly as built until you rebuild.
</Callout>

## Platform notes

### macOS

Local builds are not notarized. On first launch, macOS may ask you to confirm; that is normal for an app built on your own machine.

### Windows

The default shell can be set to PowerShell or CMD under [Settings → Terminal](/docs/settings). Most users want PowerShell.

### Linux

`pnpm build:linux` produces the Linux packages that electron-builder is configured for. Install the one that matches your distribution with your normal package tool. Nothing updates it afterward.

#### The CLI command is `orca-ide`

On Linux the [Orca CLI](/docs/cli/reference) installs as **`orca-ide`**, not `orca`. GNOME Orca — the screen reader that ships by default on Ubuntu and other GNOME desktops — already owns `/usr/bin/orca`, and Orca will not shadow it. The `.deb` and `.rpm` packages are named `orca-ide` for the same reason.

- The `.deb` and `.rpm` put `orca-ide` on your `PATH` at install time, as `/usr/bin/orca-ide`.
- With the AppImage, register the CLI from [Settings → General → Orca CLI](/docs/settings). That installs `~/.local/bin/orca-ide`.
- Inside Orca's own terminals, bare `orca` works. Orca puts a shim on the `PATH` of the terminals it manages, so agents and scripts running there use the same command as on macOS and Windows.
- On a headless host, `orca-ide serve` starts the runtime without a window. It has no network listener; use the CLI on the same machine.

Do not verify with `command -v orca`: on a GNOME desktop that succeeds and resolves to the screen reader. Use `orca-ide` in your own shell and `orca` inside Orca. If you want the short name everywhere and you do not use the screen reader, link it yourself:

```
ln -s "$(command -v orca-ide)" ~/.local/bin/orca
```
